# 테스트

`admin/index.html` 한 파일을 jsdom 에 띄워 놓고, 실제로 눌러 보면서 확인한다.
프레임워크 없이 `check(이름, 조건)` 하나로만 되어 있어 따로 배울 게 없다.

## 실행

```bash
npm install
npm test          # jsdom 테스트 (서버 없이 동작)
```

한 파일만 돌리려면:

```bash
node tests/test41.mjs
```

## 서버가 필요한 테스트

`test21-live.mjs` 는 실제로 서빙되는 주소에서 확인한다.
파일이 디스크에 있어도 **서빙되는 주소** 때문에 상대 경로가 깨질 수 있어서다.
(실제로 `/admin` 을 rewrite 로 걸었을 때 `menu/ramyeon.png` 가 `/menu/...` 로 풀려
사진이 전부 404 났던 적이 있다.)

```bash
npm run serve     # 다른 터미널에서 http://localhost:3001/admin
npm run test:live
```

## 쓸 때

- 화면을 바꾸면 테스트도 **새 의도에 맞게 고친다.** 통과시키려고 제품을 되돌리지 않는다.
- 값이 아니라 **왜 그래야 하는지**를 남긴다.
  `check('선 중심 = 점 중심', ...)` 처럼.
- 한 번 났던 문제는 단언으로 박아 둔다. 위의 사진 404 가 `test21-live` 로 남은 이유다.
